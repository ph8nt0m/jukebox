# Jukebox

사무실 공용 주크박스. 누구나 휴대폰으로 유튜브 곡을 대기열에 넣으면, 스피커가 연결된 모니터(안드로이드 TV·모니터, PC 무엇이든 브라우저만 있으면 된다)가 차례로 재생한다. 따봉·붐따로 순서를 정하고, 이모지 반응과 싱크 가사가 모니터와 모든 휴대폰에 함께 뜬다.

> An office jukebox on Cloudflare Workers. Anyone queues YouTube songs from their phone; a browser on the shared screen plays them. Votes reorder the queue, emoji reactions and synced lyrics show on every screen. No accounts — anonymous by design.

```
[휴대폰·PC 브라우저 /] ──┐
                         ├─ WebSocket ─ Cloudflare Worker + Durable Object(대기열 정본)
[모니터 브라우저 /tv] ────┘
   └ YouTube IFrame 플레이어 → 스피커
```

## 화면

손님·모니터 화면은 익명이고 접근 제어가 없다(주소를 아는 누구나 쓸 수 있다). 관리자 화면만 비밀번호로 막는다.

| 주소 | 용도 |
|---|---|
| `/` | 손님 화면: 지금 재생·싱크 가사, 다음 곡 따봉(👍)·붐따(👎), 내 곡 빼기(✕), 모두 비우기 투표, 스킵 투표·일시정지·볼륨, 이모지 반응, 검색·유튜브 링크로 곡 넣기 |
| `/tv` | 모니터 화면: 재생, 영상 아래 싱크 가사, 다음 곡, 신청용 QR, 이모지. 모니터 한 대에서만 연다(여러 곳에서 열면 같이 재생된다) |
| `/admin` | 관리자 화면(비밀번호): 대기열 맨 앞으로·한 칸 위·아래, 아무 곡이나 빼기, 따봉·붐따 초기화, 바로 넘기기, 모두 비우기, 재생·볼륨, 곡 넣기(맨 앞·맨 끝) |

## 로컬 실행

```sh
pnpm install
cp .dev.vars.example .dev.vars   # YOUTUBE_API_KEY · ADMIN_PASSWORD 채우기
pnpm dev                         # http://localhost:8787/ · /tv · /admin
```

`YOUTUBE_API_KEY` 가 비어 있으면 검색은 꺼지고 유튜브 링크 붙여넣기만 된다(oEmbed 사용).

## 배포

Cloudflare 계정과 YouTube Data API v3 키(Google Cloud 콘솔에서 발급, API 를 YouTube Data API v3 로만 제한 권장)가 필요하다.

```sh
pnpm exec wrangler secret put YOUTUBE_API_KEY
pnpm exec wrangler secret put ADMIN_PASSWORD
pnpm deploy
```

## 모니터 설정 (한 번)

1. 스피커를 연결한다(블루투스 등).
2. 브라우저로 `https://<배포 주소>/tv` 를 열고(북마크해 두면 편하다) 「탭해서 시작」을 누른다. 브라우저 자동재생 제한 때문에 처음 한 번은 터치가 필요하다.
3. 화면 꺼짐을 막는다. 자주 꺼지거나 재부팅되면 Fully Kiosk Browser 같은 키오스크 브라우저로 시작 URL·자동재생·화면 유지를 설정한다.

## 동작 규칙

- 대기열이 비어 있을 때 곡을 넣으면 바로 재생한다.
- 대기열 순서는 따봉·붐따로만 바뀐다(관리자 화면 제외): 따봉 하나에 한 칸 위로, 붐따 하나에 한 칸 아래로(맨 위·맨 아래에서 멈춤). 내가 넣은 곡에 누른 표는 수만 오르고 자리는 안 바뀐다. 기기마다 곡당 한 표, 같은 걸 다시 누르면 취소되며 한 칸 되돌아가고, 반대를 누르면 바뀌며 두 칸 움직인다(눌렀다 뗐다 반복으로 올라가지 못하게). 붐따 3개(`VOTES_NEEDED`)가 모이면 그 곡은 대기열에서 사라진다.
- 투표: 스킵과 모두 비우기는 3표가 모여야 실행된다. 다시 누르면 취소. 곡이 바뀌면 표는 비운다.
- 내 곡(같은 익명 기기 id 로 넣은 곡): ✕ 로 바로 빼거나 지금 곡이면 바로 스킵할 수 있다. 남의 곡은 ✕ 로 뺄 수 없다. 기기 id 는 브라우저 `localStorage` 의 무작위 값이고, 서버는 「내 곡인지」만 알려 주며 기기 id 는 내보내지 않는다.
- 넣기 제한: 곡 수·최근 재생·길이 제한은 없다. 이미 대기열에 있거나 지금 재생 중인 곡, 라이브(길이를 알 수 없는 영상)만 넣을 수 없다. 서버가 YouTube 에 길이를 직접 확인한다(손님이 보낸 길이는 믿지 않는다).
- 자동 재생: 대기열이 비면 지난 7일 재생 기록에서 고른다(따봉을 많이 받은 곡일수록 잘 뽑힘, 최근 1시간 곡·마지막에 스킵된 곡 제외). 자동 곡은 「🤖 자동 재생」으로 표시하고 스킵 1표로 넘어간다. 손님 접속·조작이 1시간 넘게 없으면 자동 재생은 멈춘다(빈 사무실에서 밤새 틀지 않게). 재생 기록은 DO 저장소 `history`(최근 500곡).
- 이모지: 한 번 누르면 4개가 터지고, 꾹 누르고 있으면 0.35초마다 계속 나온다. 서버는 기기당 1초에 3묶음(묶음당 최대 5개)·정해진 6개만 받고, 저장하지 않고 모니터와 모든 손님 화면에 흘린다.
- 곡 끝·재생 오류는 「지금 곡 id」가 맞을 때만 다음 곡으로 넘긴다. 중복 보고가 와도 한 곡만 넘어간다.
- 임베드가 막힌 영상 등 YouTube 가 재생 오류를 알린 곡은 자동으로 건너뛴다. 「오래 안 시작하면 넘기기」는 없다(광고 중인지 알 수 없어 광고 도중 곡을 건너뛰게 되므로).
- 광고: 임베드에도 광고가 나온다. 모니터 브라우저에 YouTube Premium 계정으로 로그인하면 빠지는 것으로 알려져 있다.
- 모니터 플레이어가 꺼져 있으면 손님 화면에 안내가 뜬다. 곡은 계속 쌓인다.

## 검색·가사

- 검색은 음악 카테고리(videoCategoryId=10)로 좁힌다. 한 쪽(25곡)에 YouTube Data API 할당량 101 units 를 쓴다(무료 하루 10,000 → 약 99쪽). 목록 끝까지 내리면 다음 쪽을 이어 불러오되, 검색 한 번에 4쪽(약 100곡)까지만(`MAX_PAGES`, `public/common.js`). 같은 검색어는 하루 동안 캐시한다(Cache API 는 커스텀 도메인에서만 동작하고 `workers.dev` 에서는 캐시되지 않는다).
- 가사: 공개 가사 DB [LRCLIB](https://lrclib.net)(키 없음)에서 싱크 가사(LRC)를 찾는다(`src/lyrics.ts`). 유튜브 제목에서 꾸밈말을 걷어 낸 검색어 몇 개로 찾고, 영상 길이와 45초 안쪽으로 가장 가까운 곡을 고른다. 결과는 DO 저장소 `lyrics:<videoId>` 에 7일(못 찾음은 1일) 둔다. 뮤직비디오는 앞뒤 장면 때문에 몇 초 어긋날 수 있다. 모니터에서는 영상 자체 자막을 끈다.

## 관리자

- `POST /api/admin/login` 이 비밀번호를 맞춰 보고 30일짜리 HttpOnly 쿠키(`jb_admin`, 비밀번호에서 만든 해시)를 준다. `/ws?role=admin` 은 Worker 가 이 쿠키를 확인한 뒤에만 DO 로 넘기고, DO 는 `admin` 태그 소켓의 `admin-*` 명령만 받는다.
- 비밀번호를 바꾸면 기존 로그인이 모두 풀린다. `ADMIN_PASSWORD` 가 없으면 관리자 화면은 막힌다.

## 배포 함정

- 배포 직후 Worker 는 새 버전이어도 Durable Object 는 몇 분 동안 옛 코드로 응답할 수 있다. 서버(`src/room.ts`)를 고치면 `CODE_VERSION` 을 올리고, `/ws` 첫 state 의 `codeVersion` 이 그 값이 될 때까지 확인한다.
